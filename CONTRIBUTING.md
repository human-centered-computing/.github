# Contributing to Human-Centered Computing

Thank you for contributing to Human-Centered Computing.

Our goal is to transform interdisciplinary research and real-world problems into open, reusable, human-centered technology and knowledge.

## Open Participation

You do not need to be a member of the GitHub organization to contribute.

Public repositories are open to participation through:

- issues,
- discussions,
- pull requests,
- code review,
- documentation,
- testing,
- research and experiment reproduction,
- design,
- localization,
- datasets where legally and ethically appropriate,
- and domain expertise.

## Before You Start

1. Choose the repository most closely related to your contribution.
2. Read its README and any repository-specific contribution instructions.
3. Search existing issues and pull requests to avoid duplicate work.
4. For substantial changes, open or join an issue before implementation so the problem, scope, and expected output can be discussed.

Small fixes such as typos, documentation corrections, or narrowly scoped bug fixes may be submitted directly.

## Contribution Workflow

### 1. Define the problem

Explain:

- what problem you are addressing,
- who or what is affected,
- why the change is useful,
- and how success can be evaluated.

### 2. Keep the contribution focused

Prefer small, reviewable changes over unrelated changes bundled into one pull request.

### 3. Provide evidence

Where relevant, include:

- tests,
- evaluation results,
- screenshots,
- benchmark results,
- citations,
- reproduction steps,
- or before/after comparisons.

### 4. Document the change

Update relevant documentation when behavior, interfaces, assumptions, datasets, models, or workflows change.

### 5. Open a pull request

A useful pull request should state:

- the problem,
- the proposed solution,
- the files or components affected,
- how the change was tested,
- known limitations,
- and any follow-up work.

## Research Contributions

Research-oriented contributions should aim to be reproducible.

When applicable, provide:

- problem definition,
- methodology,
- datasets and their licenses,
- experimental settings,
- evaluation metrics,
- baselines,
- results,
- limitations,
- and references.

Do not upload data, personal information, copyrighted material, model weights, or third-party assets unless you have the legal right and appropriate permission to do so.

## Human-Centered Expectations

Contributions should consider not only technical performance but also human impact.

Where relevant, evaluate:

- usefulness,
- accessibility,
- safety,
- privacy,
- fairness,
- interpretability,
- sustainability,
- human oversight,
- and real-world deployment constraints.

## Language

English is the canonical language for code, repository documentation, issues, pull requests, and technical discussion unless a repository explicitly defines another convention.

Multilingual documentation and localization are welcome.

## Community Roles

Participation follows a progressive model:

### Contributor

Anyone making a useful contribution through code, research, documentation, testing, design, translation, review, or domain expertise.

### Organization Member

A contributor may be invited to the Human-Centered Computing GitHub organization after meaningful or recurring participation.

Membership is recognition of contribution and continuing responsibility. It is not required to access public source code.

### Maintainer

A trusted member with ongoing responsibility for one or more projects, including review, quality, releases, documentation, and project continuity.

### Core Team

Members with broader responsibility for community direction, governance, standards, and long-term sustainability.

## Membership Criteria

There is no automatic numerical threshold.

An invitation may be considered when a contributor demonstrates one or more of the following:

- a meaningful accepted contribution,
- recurring high-quality participation,
- project or research responsibility,
- constructive review and collaboration,
- reliable technical or domain support,
- or a clear continuing role in the ecosystem.

Membership does not automatically provide write, maintain, or admin access to every repository. Access is granted according to project responsibility.

## Public Membership Visibility

GitHub may keep organization membership private by default.

Members who want their affiliation to appear publicly can change their membership visibility to **Public** from their GitHub organization membership settings.

Public visibility is optional and remains each member's choice.

## Contribution Licensing

Unless a repository explicitly states otherwise, source code in Human-Centered Computing projects is licensed under the **GNU Affero General Public License v3.0 (AGPL-3.0)**.

By submitting a pull request or other code contribution, you agree that your contribution may be distributed under the same AGPL-3.0 terms that govern the project. You retain copyright in your own contribution; this policy does not require copyright assignment to the organization.

The practical principle is simple:

- anyone may study, use, modify, and redistribute the open-source code under the AGPL-3.0 terms,
- distributed modified versions must preserve the same open-source freedoms,
- when a modified AGPL-covered program is offered to users over a network, the corresponding source must be made available as required by AGPL-3.0,
- contributor attribution and Git history should be preserved,
- third-party dependencies and assets remain subject to their own licenses.

If you cannot license a contribution under these terms, raise the licensing issue before submitting the contribution.

## Attribution

We value visible contribution.

Where technically and legally practical, project histories, commit records, acknowledgements, contributor lists, publications, and documentation should preserve meaningful attribution to the people who contributed.

## Review Principles

Reviews should be:

- specific,
- technically grounded,
- respectful,
- actionable,
- transparent about requested changes,
- and focused on improving the contribution rather than the contributor.

## Questions and New Ideas

If you are unsure where a contribution belongs, open an issue in the most relevant repository and describe the problem or idea before investing substantial work.
